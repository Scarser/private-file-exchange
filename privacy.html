Private File Exchange

Политика конфиденциальности

Дата редакции: 17 ноября 2026 года

1. Назначение приложения

Private File Exchange: частное средство для обмена файлами и совместной работы небольшой группы приглашённых пользователей. Приложение поддерживается участниками этой группы. Ответственный за вопросы доступа и обработки данных доступен по адресу professor1994@gmail.com.

Приложение использует локальные инструменты на базе rclone и Google Drive API. Оно позволяет работать с несколькими Google-аккаунтами, каждый из которых подключается отдельно с разрешения его владельца. Веб-сайт приложения содержит описание и документы; загрузка файлов и вход в Google через этот веб-сайт не выполняются.

2. К каким данным предоставляется доступ

В зависимости от выданных разрешений приложение может получать названия и идентификаторы файлов и папок, пути, типы, размеры, даты изменений, контрольные суммы, сведения о владельцах и доступе, а также содержимое файлов, необходимых для выполнения запроса пользователя. Это может включать документы, таблицы и другие файлы, доступные подключённому Google-аккаунту.

Для работы с уже существующими файлами может запрашиваться разрешение Google Drive, распространяющееся на все файлы, к которым подключённый аккаунт имеет доступ. Фактические операции выполняются с файлами и папками, указанными пользователем или предусмотренными согласованным им заданием. Разрешения отображаются на странице авторизации Google.

Приложение не запрашивает доступ к Gmail, календарю или списку контактов. Пароль Google-аккаунта приложению не передаётся. Для доступа используются OAuth-токены, предоставленные Google после авторизации.

3. Для чего используются данные

Данные используются для запрошенных пользователями операций: поиска и просмотра файлов, загрузки и скачивания, копирования между разрешёнными местами хранения, создания и обновления документов, экспорта форматов и проверки целостности копий. Перемещение и удаление выполняются только по соответствующему указанию пользователя.

Подключение аккаунта само по себе не публикует его файлы и не предоставляет другим участникам доступ ко всему Диску. Возможность открыть конкретный файл зависит от настроек доступа Google Drive и разрешений владельца.

4. Где хранятся данные

Файлы хранятся в выбранных пользователями Google-аккаунтах. При скачивании или обработке могут создаваться локальные копии и резервные копии на компьютерах, допущенных к выполнению этих операций. OAuth-токены сохраняются в локальной конфигурации клиента.

Технические журналы могут содержать имена и пути файлов, их идентификаторы, размеры, контрольные суммы, время операций и сведения об ошибках. Доступ к локальным копиям, конфигурации и журналам должен предоставляться только уполномоченным пользователям компьютера. Токены, содержимое файлов и журналы не размещаются на публичном сайте приложения.

5. Кому могут передаваться данные

Google обрабатывает данные для предоставления сервисов Drive, Docs и Sheets в соответствии со своими условиями. Файлы могут передаваться выбранным пользователем получателям или в другие разрешённые им аккаунты для выполнения запрошенного обмена. Просмотр содержимого другими участниками допускается в пределах разрешений владельца и согласованной задачи.

Уполномоченный пользователь может запускать операции через выбранные им средства автоматизации, в том числе ИИ-помощника. Если для явно запрошенной задачи нужны метаданные, технический результат или содержимое файла, необходимые данные могут передаваться выбранному сервису с согласия пользователя. Такая обработка должна ограничиваться выполнением задачи; полученные через Google API данные не используются для обучения универсальных моделей искусственного интеллекта или машинного обучения.

Данные не продаются и не используются для рекламы, рекламного профилирования, определения кредитоспособности или передачи посредникам, торгующим данными. Передача также возможна, если она необходима для безопасности или исполнения применимых требований закона.

6. Срок хранения, отключение и удаление

Файлы и локальные копии сохраняются, пока они нужны для согласованной работы или пока уполномоченный пользователь не удалит их. Технические журналы сохраняются в объёме, необходимом для проверки операций и устранения ошибок.

Владелец аккаунта может в любое время отозвать доступ в настройках Google-аккаунта: https://myaccount.google.com/connections. После отзыва приложение больше не сможет использовать это разрешение для новых обращений к Google API. Уже скачанные или переданные с согласия пользователя копии автоматически не удаляются.

Чтобы удалить подключение, локальные токены или копии, находящиеся под контролем группы, напишите на professor1994@gmail.com и укажите, к какому аккаунту или файлам относится запрос. Для защиты данных может потребоваться подтверждение, что запрос исходит от их владельца. Копиями, которые получатели самостоятельно сохранили в своих аккаунтах, распоряжаются соответствующие получатели.

7. Защита данных и публичный сайт

Обращения к Google API выполняются по HTTPS. Реквизиты доступа не включаются в опубликованные файлы сайта и не запрашиваются по электронной почте. Владельцам устройств следует защищать учётные записи и ограничивать доступ к конфигурации приложения и резервным копиям.

На информационном сайте нет собственных рекламных инструментов, форм сбора файлов и средств аналитики. Хостинг GitHub Pages может обрабатывать технические сведения о посещениях в соответствии с политикой GitHub: https://docs.github.com/en/site-policy/privacy-policies/github-general-privacy-statement.

8. Требования Google и изменения политики

Использование и передача данных, полученных через Google API, должны соответствовать Google API Services User Data Policy, включая требования Limited Use: https://developers.google.com/terms/api-services-user-data-policy.

При существенном изменении целей или порядка обработки политика обновляется до начала новой обработки; затронутым пользователям сообщается об изменениях и, когда необходимо, запрашивается новое согласие.
